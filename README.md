# Shared Brain

跨 Agent 的本地记忆工具：自动加载项目记忆、记录会话进展，启用维护后还能从经验中提炼技能。

[![Platform: Windows 10 / 11 x64](https://img.shields.io/badge/Platform-Windows%2010%20%2F%2011%20x64-0078D4.svg)](https://github.com/Denis-Tang/second-brain/releases/latest)

Shared Brain 是给个人开发者准备的轻量本地记忆工具。完成 MCP 和 Hook 接入后，Agent 会自动加载并按当前任务检索记忆，在阶段结束或会话收尾时自动生成和保存总结。换个会话或工具，也能沿用已有的项目记录，不用反复交代背景。

项目优势：
- 减少部分情况因压缩上下文带来的损耗和多余花费。
- 解决项目跨agent开发不便的痛点。
- 用户资料储存在本地并且便于查看。
- 相比向量知识库：更加轻量，维护成本更低，索引速度相当，资料储存在本地。
- 配置简单并且使用外部mcp工具，避免因为agent版本更新而失效


**当前源码版本：0.5.1。** 下载版本与更新说明以 [GitHub Releases](https://github.com/Denis-Tang/second-brain/releases/latest) 为准；源码中的新增功能不代表已有安装包已包含。

0.5.1 恢复桌面首帧绘制等待：WebView2 完成首帧捕获后才显示亚克力窗口，避免 0.5.0 导航完成后过早露出空白玻璃。原生窗口测试检查首次启动、再次启动及最小化恢复后的实际像素。

系统从睡眠或休眠恢复后，程序会重建网页显示控件；窗口最小化或藏在托盘时，延后到再次打开时重建。后端及已保存配置保留，页面会重新加载，未保存的表单内容需要重新填写。

## Preview / Demo

程序提供三个页面：

| 页面 | 用途 |
| --- | --- |
| 总观 | 查看知识积累、会话数量和历史趋势，编辑全局提示词 |
| 项目配置 | 管理两层项目树与工作目录，查看关联资料、提交和合并子项目成果 |
| 设置 | 选择知识库与明暗外观，查看 Agent 接入记录、复制接入提示词，配置可选维护与费用 |

完成 MCP、薄入口与宿主支持的 Hook 接入后，典型流程为：

```text
完成一个阶段或会话收尾 → Agent 自动生成总结并保存项目进度
                         ↓
打开新会话 → Agent 自动加载项目记忆 → 按任务自动检索 → 继续工作
```

可运行版本见 [Releases](https://github.com/Denis-Tang/second-brain/releases/latest)。本 README 暂未收录与当前源码对应的界面截图。

## Features

- **自动加载与检索记忆**：接入规则与启动 Hook 提醒 Agent 加载全局提示词、项目状态和相关记忆；任务明确后，Agent 按需自动检索补充资料。
- **自动生成会话总结**：Agent 在有用阶段或收尾时生成完整的最新总结并调用 MCP 保存；收尾 Hook 提醒补全漏存的总结。
- **跨会话、跨客户端复用**：不同客户端连接同一知识库与应用数据目录，自动读取已有项目状态。
- **本地 Markdown 资料**：总结、项目记录、知识和技能保存在 Obsidian 可读文件中；代码和交付物留在原工作区。
- **显式项目归属**：按用户配置的工作目录匹配项目，更具体的子目录优先，临时切换目录不改变会话工作区。
- **中英文与代码检索**：支持 `auto`、`text`、`code` 模式，增量刷新索引，代码查询可利用文件名、路径和标识符。
- **独立会话总结**：未匹配项目的会话也能保存总结；不创建默认项目，默认检索全部资料，独立总结不进入维护队列。
- **错误与成功反馈**：记录实际失败及适用条件，后续成功可更新提醒，保留历史依据。
- **可选增量维护**：在明确启用和预算约束下整理项目知识、合并经验、生成技能记录；不自动安装或执行技能。
- **桌面更新入口**：检查发布、下载校验，以及满足条件后的原路径替换与重启。

## Quick Start

### Requirements

- 桌面运行环境：Windows 10 22H2 x64 / Windows 11 x64、WebView2 Runtime。
- 一个放在源码目录之外的本地知识库目录，推荐使用独立、干净的 Obsidian Vault。
- 支持 MCP 的 Agent 客户端。Hook 是否可用取决于具体宿主事件支持与配置。

Windows 分发包包含 Python、.NET 桌面运行时和 Node.js，无需为运行安装包另装这些运行时。源码开发与构建要求见 [Development](#development)。

### Installation

1. 从 [Releases](https://github.com/Denis-Tang/second-brain/releases/latest) 下载 Windows x64 ZIP。
2. 完整解压，保留 `shared-brain.exe` 同目录下的 `_internal`、`desktop`、`integrations` 和 `runtime`。
3. 运行 `shared-brain/shared-brain.exe`。

### Run

首次使用可在设置页打开并查看“配置引导”。
1. 在“设置”中选择要新建的知识库路径，点击“保存设置”。
2. 复制内置接入提示词，交给需要接入的 Agent，按实际宿主能力配置 MCP、薄入口和 Hook。
3. 在“项目配置”中添加项目与工作目录（需要和agent中的工作区路径保持一致）；未匹配目录的会话视为独立会话。
4. 配置负责从日常总结中提炼技能的模型（可选）
5. 重启 Agent 并新开会话，确认启动时已自动加载记忆、收尾时已生成并保存总结。日常使用无需逐次手动要求这两项操作。

第二个及后续客户端复用同一 Vault 和 home，只补接入配置，不重新初始化或重建资料。路径修改但尚未保存时，接入提示词不可复制。

设置页“外观”支持跟随系统、浅色和深色，默认跟随系统。“Agent 接入”显示最近成功调用 `bootstrap` 的宿主与时间；“已接入”是成功加载记忆的历史记录，不代表实时在线或 Hook 已验证。当前仍使用接入提示词，尚未提供自动修改宿主配置的安装器。

项目页按创建时间倒序显示根项目；名称旁的小圆点表示有子项目，点击卡片打开该组项目的悬浮树状窗口。卡片支持“简洁 / 详细”和单独展开，显示状态按知识库保存。“资料目录”展示项目资料的真实路径；工作目录可在编辑中移除，保存后生效。滚动条在停止滚动 2 秒后隐藏，悬停或拖动时保持可见。

## Usage

### 项目与会话

“新增项目”创建项目及工作目录映射，“编辑”修改已有项目。主项目菜单中的“新建子项目”建立第二层，每个子项目只属于一个主项目。父子项目分别选择不同的已有工作目录，目录不必在文件系统中互为父子。一个项目可关联多个目录；同一路径只能归属一个项目，父子目录配置到不同项目时按更具体的路径匹配。项目名称和 Git remote 不参与识别。

子项目检索实时继承主项目的知识、技能和资料，保存仍归子项目；主项目不自动检索未合并的子项目成果。在子项目“提交与合并”中选择知识、技能、资料、决策、任务、进度或会话总结，提交保留当时内容，再由用户合入主项目；有冲突时逐项选择保留主项目或采用提交内容。这是成果管理，不操作 Git 仓库。

Agent 在项目会话中自动生成并保存完整的最新总结，同时更新目标、进度与下一步；同一会话持续更新同一份总结。独立会话同样自动生成和保存总结，但不创建项目卡、任务或决策。切换客户端后，需要使用相同的 Vault 和 home 才能读取同一份资料。

会话总结保留原位。“资料与会话”可查看正文、“来源”和“引用这篇文档”，按已有来源关系关联知识与总结；新保存的来源也生成 Obsidian 可用链接，不会自动为无关联的历史总结猜测主题关系。合并会话时保留原总结，在主项目增加索引和成果引用。

上述自动流程由接入规则、Hook 与 MCP 配合完成：启动 Hook 提醒 Agent 调用 `bootstrap`，Agent 根据任务自动调用 `search` 补充记忆；阶段结束时 Agent 生成总结并调用 `save`，收尾 Hook 检查并提醒补全漏项。这里的“自动”指无需用户每次手动下达加载或总结指令，实际内容由 Agent 生成与保存，并非 Hook 直接复制完整聊天。

<details>
<summary>项目创建、删除、恢复与历史资料规则</summary>

“项目配置”用两层树展示项目和数量，同级项目按创建时间从新到旧排列，编辑或改名不改变顺序；右上角“新增项目”打开独立创建窗口。填写名称并通过“添加文件夹”选择一个或多个已有工作目录；“创建项目”保存后返回列表，可再次点击“新增项目”添加其他项目。每个项目的“编辑”只修改该项目，与新增入口分开。保存后自动创建 `项目/<资料目录>/项目.md` 和 `会话索引.md`；任务、决策按需创建。一个目录只能配置给一个项目；父子目录配置到不同项目时，子目录及其后代归更具体的项目。支持复制项目名称；“复制路径”仅放在具体工作目录后，每次只复制该条路径；不自动创建各 Agent 宿主的工作区。仍有子项目时不能删除主项目。

列表包含原有项目，可直接编辑并补充路径。允许移除全部路径，项目卡与历史总结保留，项目不再参与匹配。改名仅更新显示名称，保留 ID、原资料目录和已有链接。点击“删除项目”先弹出确认框，仅“确认删除”执行删除；取消或按 Esc 不作修改。删除移除立项和路径绑定，将项目卡原样转存为同目录 `立项归档.md`；会话索引、总结、任务、决策、用户原始资料和工作目录保留，不再参与原项目归属。工作目录搬迁后在此页修改路径；同名目录与 Git remote 不参与判定。

根项目删除后，用原资料目录名称新增根项目，会恢复该目录中的立项归档及原项目 ID，并重新绑定所选工作路径，保留历史进度和资料；可反复删除、恢复。子项目删除后同名新建会获得新 ID 和资料目录，原历史资料保留，不自动恢复原子项目。没有程序生成的立项归档时，不覆盖同名的用户资料目录。

bootstrap 返回 `project_directory`（项目资料绝对路径），独立会话为空。Agent 使用 save 更新项目卡、任务、决策与总结索引；项目经验放在项目的 `知识/`。所有会话发生安装、卸载、工具配置、skills、模型及电脑环境变更时，通过 `changes` 写公共独立知识池；普通源码修改留在项目记录。对象用稳定名称标识，保存实际位置、最新状态、验证和变更历史。配置变更后重新 bootstrap；save 和失败 Hook 也重新匹配。旧知识、技能、资料与历史总结不迁移或改写；独立会话总结、平铺经验和导入资料不进入维护队列。

升级后旧的 Agent 路径绑定不再生效；请在项目配置页为原项目添加目录，重新复制接入提示词并更新宿主 Hook 适配文件。MCP 已移除 choice、project、project_name 启动参数和 needs_choice 返回字段，重启 MCP 连接以刷新工具定义。

</details>

### 常用命令

```powershell
# 查看版本
shared-brain --version

# 输出当前安装的 MCP 连接配置
shared-brain config-mcp

# 使用指定应用数据目录启动 MCP
shared-brain --home "C:\Users\YourName\.shared-brain" mcp
```

通过分发包执行时，将 `shared-brain` 替换为实际的 `shared-brain.exe` 路径。命令说明可用 `shared-brain --help` 查看。

### 全局提示词与草稿

在“总观”编辑全局提示词，保存到 `知识/全局提示词.md`。正文非空时 `bootstrap` 全文返回；Agent 不自动编辑这份文件。

草稿由用户在 Obsidian 管理并手动提供给 Agent。草稿不索引、不搜索、不统计、不注入，也不参加维护。

### 更新与解绑

点击界面左下角的版本号检查更新。下载并校验只保存 ZIP；自动替换前需退出占用安装目录的其他 `shared-brain.exe` 进程，包括宿主 MCP 连接。更新后重启宿主或重新连接 MCP，以刷新工具定义。

退出接入时，在设置页复制“解绑提示词”交给对应 Agent。按提示移除该宿主接入，并改为直接读写已有 Markdown；知识库与应用数据保留。

<details>
<summary>更新检查、下载、替换与回滚细节</summary>

界面左下角「已就绪」上方显示当前版本号。点击它检查 GitHub 上的最新发布并显示结果：有新版本时给出这一版的更新说明、「下载并校验」「复制更新提示词」按钮和发布页链接；已是最新或暂时查不到时只说明情况，不提供这些按钮。

「下载并校验」把新版 ZIP 下载到应用数据目录 `updates/<版本>/`，边下边算 SHA256：与发布资产给出的 SHA256 不一致、大小不符或压缩包结构不对就删除并报错，校验通过才留下，并记录版本、SHA256、大小和校验时间。弹窗显示下载进度，可以取消；已存在校验通过的包时不重复下载。**这一步只写应用数据目录，不替换、不移动正在运行的程序**；完成后可以「打开所在文件夹」查看。

更新检查与下载都只在点击时发起，不发送知识库或应用数据。检查结果缓存 6 小时，一分钟内重复点击不重复请求；匿名调用 GitHub 接口按出口 IP 限流，配额用尽时提示稍后再试并沿用上一次的结果，不反复重试。

下载校验完成后，弹窗会出现「立即更新并重启」。程序先确认没有其他 `shared-brain.exe` 在运行——宿主的 MCP 子进程还在时就停下来提示先退出 Codex / Claude Code / DeepSeek Harness 的连接或重启宿主，不会替你结束任何进程。确认后把新包解压到安装目录同卷的暂存目录，再交给一个独立脚本在程序退出后完成替换：等待全部进程退出 → 旧目录改名备份 → 新目录就位 → 用 `--version` 自检新版本 → 启动 → 成功后清理备份；任何一步失败都会把旧目录改回来。进度写在应用数据目录的 `update-state.json`，下次启动若发现上次没做完会明确报告。替换脚本与日志留在暂存目录，可以直接查看。

复制到的「更新提示词」交给 Agent 完成替换：确认没有 `shared-brain.exe` 进程占用、校验 SHA256（已下载并校验过时直接用本地包）、备份原目录、解压回原路径、验证版本号，失败则回滚。关键点是**覆盖到原安装目录**——MCP 与 Hook 配置里写的是该目录的绝对路径，路径不变就不需要修改任何配置；换成新目录解压则必须重新复制接入提示词。

不打开桌面的用户可以直接查版本：

```powershell
shared-brain --version
```

更新后请重启 Codex / Claude Code / DeepSeek Harness 的会话或宿主：MCP 客户端在会话开始时缓存工具列表，不重连就不会使用新的工具定义。

</details>

## How It Works

```text
宿主 Hook + 接入规则
              ↓ 提醒 Agent 执行记忆流程
Agent 客户端
  ├─ bootstrap：自动加载全局提示词、归属与项目状态
  ├─ search：根据任务自动按范围检索资料和适用错误
  ├─ save：保存 Agent 自动生成的总结、项目进度及实际变更
  └─ feedback：补充成功结果，修正错误提醒
              ↓ MCP / 本地服务
       Markdown 知识库 + 应用数据目录
              ↓ 可选、受预算约束
       增量维护 → 知识 / 技能记录
```

Markdown 保存可阅读的资料，SQLite 保存索引和运行状态。搜索前根据文件修改时间、大小与必要的内容校验刷新索引，避免稳态下反复读取未变化文件。近期写入处于时间戳不可信窗口的文件会再次校验。

项目由应用配置的路径决定。工作区优先取宿主提供的启动根目录，否则取启动目录；不按 Git 根目录自动提升。`bootstrap` 和保存时重新核对匹配关系。项目会话检索应传项目 ID；独立会话默认检索全部；`project="independent"` 只查公共池，`project="all"` 查全部。

启动和检索不调用维护模型。夜间维护默认关闭，启用后才按配置调用模型；“测试连接”也会访问所配置端点。

### 用户知识库

```text
会话总结/<Agent>/YYYY/MM/日期-会话标识.md   # 项目与独立会话
项目/<名称>/项目.md
```

## Configuration

桌面设置保存至应用数据目录的 `settings.json`。默认 home 为 `~/.shared-brain`，Windows 对应 `%USERPROFILE%\.shared-brain`；MCP、Hook 与桌面应指向同一 home。

| 配置 | 用途与默认值 |
| --- | --- |
| `vault_path` | 用户选择的知识库路径 |
| `base_url` | 维护模型端点，默认 `https://api.deepseek.com` |
| `model` | 维护模型，默认 `deepseek-flash` |
| `maintenance_enabled` | 是否启用自动维护，默认 `false` |
| `maintenance_time` | 本机维护时点，默认 `02:00` |
| `SHARED_BRAIN_HOME` | 指定应用数据目录 |
| `--home PATH` | 为本次命令指定应用数据目录 |
| `SHARED_BRAIN_TEST_EXE` | 为分发包测试指定待测 EXE |

API key 存在操作系统凭据库中，不回显；设置保存凭据引用。home 还保存项目路径映射、SQLite 索引、图表历史、维护进度、错误报告和费用账本，不能把它视为只有可丢弃缓存的目录。

维护费用核算目前只支持已实现的 DeepSeek 官方端点与模型价格规则；可填写端点不代表其他 Provider 的费用与行为已验证。详细额度及结算规则见下文。

## Advanced Usage

### MCP 工具与错误反馈
`shared-brain config-mcp` 输出本次安装的可执行路径与参数，MCP 服务名统一为 `shared_brain`；宿主启动 `shared-brain mcp`。提示词也包含相同配置，不包含密钥。

| 工具 | 用法 |
| --- | --- |
| `bootstrap` | 必填 cwd、稳定 session_id、agent。可传 workspace_root、task_id、task（最多500字符）；返回非空 global_prompt 全文、项目上下文及最多3条与当前任务相关的知识/技能。 |
| `search` | query，project=项目 ID 查本项目；子项目另实时继承主项目的知识、技能和资料，任务、会话和错误不继承。independent 仅公共池，空值/all 搜全部。mode=auto 自动区分中文散文与代码风格查询，可显式传 text 或 code，返回的 mode 说明实际用法。独立会话默认全部，项目不默认搜公共池。返回来源、条件、依据和最多3条错误线索；不调用模型。 |
| `save` | 根身份 context；所有会话的 summary 是完整最新总结，goal/progress/next_actions 更新项目。changes 含 object/action/location/state，可附 evidence/conditions；所有会话写公共对象。errors 单独保存；收尾核对后 errors_reviewed=true。 |
| `feedback` | 根代理在实际成功并读回效果后提交 error_session_id、error_id、observation（target/method/environment/evidence）。 |
| `status` | 就绪、待处理量、统计与本月费用/预留；不调用模型。 |

只保存有用阶段，不记录每次工具调用。子代理向根代理回传。项目的 `memory={title,body,verified,evidence,conditions}` 可当场保存经验；verified=true 需要实际结果依据。独立会话同样通过 summary 保存完整总结，通过 changes 保存指定变更，不另写普通经验；归属仍为空，默认检索范围仍为全部。

错误项包含 target、method、symptom，可补 environment（文本键值表）、attempts、workaround、impact=low/high、id。同一会话同一对象/方法/条件默认合并，也可沿用 id 补充尝试；每会话一份 JSON，无错不建空报告。仅记真实失败，不按 fail 字符串推断因果。URL 去掉凭据、query 与 fragment；影响适用性的非敏感 query 参数应写入 environment。不得提交完整工具输出、命令或秘密。

失败保存后即可检索。检索优先按项目与显式对象/方法/环境过滤，再按关键词和时间排序；未知条件要由 Agent 核对。知识与错误共用切词：中文连续段按二字滑窗，单字保留，中英混合保留英文词，去重后最多512词，排除“怎么、然后、一直”；中文查询至少3个有效词时须命中2个，显式指定错误对象仍按对象匹配。中文按命中词数排序，纯英文长词保留FTS，短词保留子串匹配。bootstrap 只带强相关高影响提醒，最多2条约120估算 tokens；search 错误部分最多3条约300估算 tokens，放不下完整适用条件则省略，而非截断条件。原报告可按返回路径读取。

同一对象/方法且已知环境完全一致的成功，撤下当前失败提醒但保留历史；不同方法成功增加绕行；新环境或未知条件保留不同观察。依赖原错误的知识暂时退出当前检索，待维护补充结果。维护在额度内将同归属的待复核知识/技能提供为旧结论，即使沿用原标题也须等报告分组全部处理完才解除隐藏；已合并条目继续隐藏，解除标记不会使已处理条目重新排队，未处理完的正文进度保留。冲突记录带 conflict=true，仅当前任务需要选择时询问用户。
### 宿主接入

接入说明与配置示例见 [integrations/README.md](integrations/README.md)。适配文件随包提供，是否启用 Hook 仍需核对具体宿主支持。

<details>
<summary>Hook 事件协议与支持边界</summary>

0.5.0 分发包提供 Codex、Claude Code、旧 Oh-DSH 和 DeepSeek Harness 的生命周期适配，并包含 [宿主接入](integrations/README.md) 说明。内置提示词指向这些现成脚本；Codex / Claude 命令 Hook 使用包内 `runtime/node.exe`。已发布的 v0.4.0 ZIP 只包含 DeepSeek Harness 适配。不要直接把 Harness 插件用于旧 Oh-DSH。

内置提示词给出真实程序位置的 `shared-brain --home PATH hook` 命令。它从 stdin 接收一个 JSON 事件并输出一个 JSON 对象；已有适配按随包说明接入，其他宿主才需要按其文档映射事件/返回格式。程序不擅自安装 Hook。

每个事件包含宿主真实 role、session_id、root_session_id；子代理事件忽略。事件约定：

- `start`：返回 additionalContext，提醒调用 bootstrap。
- `turn`：每个新用户回合重置收尾状态；模型续答/工具调用不能重置。
- `closeout`：项目或独立会话漏总结、实际错误未核对时提醒一次；独立会话保存总结并核对指定变更与错误。支持可选稳定 turn_id。Hook 不读取操作内容，实际变更由执行 Agent 主动保存。
- `failure`：可选，默认不装。actual_failure=true、error 为精简错误项，只落盘并返回空对象。expected_probe=true 忽略。无模型调用、无重试指导、无上下文注入。

已实现和测试的是上述程序端协议。具体宿主必须确认支持启动、新用户回合、可继续的收尾事件后再安装；不支持时保留主动薄入口，并明确未启用的 Hook。失败 Hook 若影响任务质量则不装。可通过移除接入 Agent 添加的 Hook 配置关闭。

</details>

<details>
<summary>DeepSeek Harness 原生接入</summary>

`integrations/deepseek-harness.mjs` 提供 Harness 0.1.7 的原生生命周期适配。它通过实际运行时 agents.roots() 区分根与子代理，以 source.kind=user 识别新用户输入，补写消息不重置收尾提醒。只传会话身份和事件，不读取原生会话或工具输出，不安装失败 Hook。

### 可选维护与费用

默认关闭；用户在设置启用后，应用运行期间每天本机时间02:00处理增量和积压。Windows 桌面只运行一个实例，不同安装目录或 home 再次启动都显示已有窗口，也能识别未使用单实例机制的旧版桌面；关闭窗口仍在托盘，只有右键托盘选择“退出”才结束应用。MCP 和 Hook 不受桌面单实例限制。错过时点后下次启动可补处理。每日批次额度与费用记录跨重启保留。`shared-brain maintain` 手动处理也共用额度。

费用核算目前支持官方 `https://api.deepseek.com` 的 `deepseek-flash`（V4.1 Flash），明确关闭思考。月上限人民币10元；北京时间每日最多3个请求，累计输入30,000、输出30,000 tokens，每批最多输出10,000 tokens。每批最多4项，超长资料分段处理，未处理尾部保留。无新增无请求；同批重复内容本地去重，只有相关旧知识进入输入。

项目总结按正文版本保留提炼进度，处理中途保存不会重头开始；先完成正在处理的版本，再按行提交新旧正文的增删改及前后两行上下文。正文未变时只同步处理标记，不调用模型；失败不推进进度。旧进度没有正文快照时，文件未变可沿用偏移，已改变的旧版本无法还原，首次按当前全文建立基线。

调用前按UTF-8字节上界加消息开销计算输入预留，并按高峰价格预留费用；有可信 usage 后按实际输入、缓存命中与输出结算。已计费但内容格式错误的响应仍结算；网络失败或缺 usage 保留最大预留，不自动重试。设置页显示已用/预留与剩余费用。预算不足停止新请求，保存/search不受影响。

单价依据2026-09-27官方文档：空闲时段每百万输入1元、缓存输入0.02元、输出4元，高峰两倍；节假日按普通工作日保守核算。价格变化需更新费用核算；账本仅限制本应用维护，不包含其他客户端或手动连接测试。测试连接会调用配置端点。

维护在同一材料归属内补充知识、合并重复经验、从完整实际成功过程生成技能；项目材料产出到本项目，公共材料产出到独立项目。技能保存成功依据及来源，不自动安装或执行。对象历史分段处理，每段同时提供最新事实与已有整理经验；未处理尾部跨维护轮保留。整理仅更新“整理经验”，具体位置、当前状态、真实变更历史及验证保留。合并条目保留正文和 merged_into，不删除原文；生成内容不自动成为已验证。全局提示词、草稿与旧导入资料不参加维护。

更新同名知识或技能时，模型须基于 existing 中的完整旧正文返回整理后的完整新版，替换生成正文并累计保留来源，不再逐次追加。若旧正文未检索到或超出本批额度，同名覆盖会报错并保留原文及未完成的材料；需处理检索或篇幅问题后再维护，不自动重试。总结差异中的删除表示原文变化，不直接视为旧结论已被证伪。

### 检索、接续与质量评测

以下保留历史实验的条件、数据与限制。它们不是每次发布重新测得的结果，也不构成普遍速度、质量或费用承诺。

<details>
<summary>增量索引、路径修正与检索方案对照</summary>

索引刷新按文件的实际变化走：程序用目录遍历拿到每个 Markdown 的修改时间与大小，只有变化过的文件才会被读取和计算哈希，未变化的文件不读、不算。`status` 与维护判断只看已有索引，不再触发全量扫描；夜间维护自己先刷新一次。旧版本的索引会自动就地升级，项目映射、会话状态和维护进度都保留。

`search` 的检索模式默认 `mode="auto"`：中文走二字滑窗的子串匹配，形如标识符、路径或文件名的查询（`vault.py`、`force_refresh`、`refresh()`）自动按代码处理，拆分 camelCase/snake_case 并给标题与路径加权。已知查询类型时可显式传 `mode="text"` 或 `mode="code"`；返回的 `mode` 字段说明实际使用的模式。打分、命中覆盖与排序都在 SQLite 内完成，只取需要的条数，命中很多时不再把所有正文读进内存。

改造前后同机实测（自建笔记，中位数，含刷新；稳态下未变化文件的读取次数为 0）：

| 笔记数 | 刷新（改造前 → 后） | 中文检索（前 → 后） | 未变化文件的读取次数 |
| ---: | ---: | ---: | ---: |
| 200 | 15.7 → 6.9 ms | 19.0 → 9.8 ms | 0 |
| 1,000 | 74.5 → 22.0 ms | 78.9 → 30.6 ms | 0 |
| 3,000 | 249.0 → 57.5 ms | 248.4 → 84.7 ms | 0 |
| 10,000 | 未测旧版，现为 187.2 ms | 现为 286.2 ms | 0 |

刚被写过的文件处在时间戳不可信的窗口内时会再校验一次内容，因此保存后紧接着的少量刷新会略慢，之后回到稳态。项目自带基准 `scripts/search_benchmark.py` 在同一份合成数据上：5,000 篇从 413.6 ms 降到 108.0 ms，命中仍是 100/100。`status` 在 1 万篇上约 20 ms（改造前每次都会全量重扫）。这些是合成笔记与本机数据，不是模型检索质量评测。

#### 相关实验

英文 FTS 索引现在包含笔记的相对路径、标题和正文，修复「标识符只出现在文件名中，候选阶段就被漏掉」的问题。已有索引在首次刷新时从 `notes` 重建检索表，不重新读取未变化笔记，保留项目映射与维护进度；新建和修改的笔记直接索引路径。检索模式、评分与排序保持原样，没有切换 BM25 或引入新分词依赖。

本机 Python 3.11 / SQLite 3.45.1 的隔离实验中，仅补入路径使 24 道有答案场景题的前五命中从 **23/24 提升到 24/24**；另 3 道无答案场景题均无返回。固定的 30 道历史查询，修正前后的完整检索结果 **30/30 一致**。这组历史题包含 27 道有答案题，当前前五命中 **25/27**，3 道无答案题仍有误检；不能把结果一致当作所有问题都已答对。

同日还比较了双字倒排候选、BM25、代码优先路由。最好的倒排原型使用不重复存正文的 FTS 表，并与现有增量刷新合并；以下为同轮 `BrainService.search` 中位耗时，包含刷新、结果格式化与错误检索，知识库由隔离副本提供，查询顺序打乱、各重复 6 轮：

| 语料 | 当前实现 | 双字倒排原型 | 差异 |
| --- | ---: | ---: | ---: |
| 176 篇真实笔记、30 道历史查询、28 份错误报告 | 37.29 ms | 36.84 ms | 快约 1.2%，P95 无改善 |

## 项目边界与局限

| 边界 | 对实际使用的影响 |
| --- | --- |
| **自动化依赖宿主与 Agent 执行** | 推荐使用当前主流模型进行首次接入和宿主升级后应验证完整流程；MCP工具的调用以及HOOK相关更加适合256K以上的上下文模型。 |
| **总结可能丢失部分细节** | 保存的是 Agent 整理的状态和经验，不是完整聊天录像。Agent 可能遗漏、误解或保存过时结论，但是如有需要可以自行检查修改。 |
| **检索以词语和路径匹配为主** | 当前未采用嵌入式语义检索。换一种说法、隐含关系、宽泛查询和无答案问题仍可能漏检或误检；历史 27 道有答案题中前五命中为 25/27，3 道无答案题仍有误检，具体实验条件见后文。 |
| **索引扩容仍有局限** | 较大的知识库和宽泛查询会增加耗时，不推荐用于高精度项目以及生产级项目的开发，推荐个人开发场景使用。 |
| **技能提炼有范围与费用限制** | 维护默认关闭，启用后按预算处理支持的增量材料；独立会话总结、草稿和全局提示词不参加维护，生成的是可复用技能文件。同时该功能支持选择性开启，不会影响记忆的索引 |
| **共享记忆不等于完整迁移环境** | 多客户端需连接同一份 Vault 和 home；本项目不提供云端同步。代码、依赖、权限及宿主配置不会随会话总结迁移，自动记忆也不能替代这些准备。 |
| **多出的少量花费** | 工具的调用以及会话总结的产生会导致额外产生一些花费。但是相比多数时间由压缩会话产生的预期费用以及细节丢失造成的重新开工成本，本工具产生的花费相对低廉，但仍需注意超长任务带来的新会话输入成本。 |

提示：接续结果不完整时，可直接核对 Markdown 中的总结、项目状态及引用来源；需要完整聊天历史时，仍应使用宿主自身的会话记录。

## FAQ / Troubleshooting

**新会话会自动知道知识库的全部历史吗？**

新会话会自动加载项目状态和少量相关记忆，再由 Agent 根据任务逐步检索，不会一次读取整个知识库。接入正常时，Agent 在有用阶段或收尾时自动生成并保存总结；未保存的聊天细节不会自动恢复。

**没有配置项目的会话怎么办？**

保持独立，由 Agent 自动生成和保存会话总结；不自动创建默认项目。默认检索范围为全部资料，按任务取回相关结果，并非遍历加载全部正文；独立总结不进入维护队列。

**为什么启动或收尾 Hook 没有触发？**

先确认当前宿主支持对应事件、使用正确适配、已启用配置并完成宿主要求的信任步骤。直接执行适配脚本成功只证明协议链路，不证明真实宿主已触发 Hook。必要时重启宿主并用新会话验证。

**为什么更新后界面或 MCP 工具没有变化？**

确认运行的是新版安装目录；只拉取源码不会替换旧安装包。退出旧桌面及占用程序的宿主连接，再启动新版，并重连 MCP。自动更新要求原路径替换，以保留配置中的绝对路径。

**关闭窗口后为什么程序仍在运行？**

关闭窗口会隐藏到托盘，选择托盘“退出”才结束桌面与夜间维护。桌面单实例不限制 MCP、Hook 子进程。

**总观的 token 数是 API 用量吗？**

不是。它估算知识正文的新增量，删除不抵消新增，草稿与全局提示词不计入。斜纹表示没有记录，首次升级不补造历史；API 维护费用在设置页单独显示。

**不用 Shared Brain 后，资料还能使用吗？**

可以。知识库是 Markdown 文件。使用设置页的解绑提示词清理当前宿主接入，保留知识库与 home；后续可由其他工具直接读写文件。
